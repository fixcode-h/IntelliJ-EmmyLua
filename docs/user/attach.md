# 附加调试（Windows）

把调试器附加到正在运行的游戏或 UE 编辑器，不用在游戏里加任何代码。支持 x86 / x64、Lua 5.1–5.4（UnLua 是 5.4）。

## 开始

1. 打开游戏或 UE 编辑器（PIE 跑不跑都行）。
2. IDE 里 `Run` → `Attach to Process…`，在「Lua 附加」分组里选进程。装了 UELink 的 UE 编辑器 / 游戏排在最前，标着项目名。
   也可以新建运行配置「Lua 附加」，以后一键附加。
3. 在 `Content/Script` 下的 Lua 文件里下断点。

附加时编辑器里还没加载 Lua（比如 PIE 没开始）也没关系：调试控制台显示「等待目标进程加载 Lua」，开始 PIE 后自动连上。

## 启动并附加

要调程序一启动就跑的 Lua（模块顶层代码、GameInstance 初始化、打包游戏的启动流程），用运行配置「Lua → 启动并附加」：
填程序（`UnrealEditor.exe` 或打包后的游戏 exe）、参数（例如 `"D:\MyGame\MyGame.uproject" -game`）和工作目录（默认程序所在目录），
然后点调试。IDE 启动程序时，在它执行任何自己的代码之前就装好调试器，第一个 Lua VM 会等 IDE 下完断点才开始跑，启动阶段的断点也能停住。

- 位数按 exe 自动判断；参数里可以用 `$PROJECT_DIR$` 等宏。
- 默认停止调试时关闭程序；想让编辑器继续开着，关掉「结束调试时关闭程序」（关闭程序会丢掉没保存的改动）。
- Agent 也能用：`lua_debug_session action=launch` 按运行配置名启动。

## 能做什么

- 行断点、条件断点、命中次数、日志断点（只打印不停）
- 单步进入 / 跳过 / 跳出、运行到光标
- 变量、监视、悬停、行尾变量值、求值窗口；修改变量的值
- 协程：线程下拉框里切换
- 出错即停：断点窗口里打开「Lua 错误」，脚本报错时停在出错行
- UE 对象：装了 UELink 时，UObject 按声明类分组显示全部属性、组件和函数
- 采样性能分析：调试中开始采样，看最耗时的函数，双击跳到源码
- 保存后重载到 UE：设置 → 工具 → EmmyLua 调试 →「保存 Lua 文件后自动重载到 UE」，或编辑器右键「重载到 UE」（Ctrl+Alt+R）

## 断点不停怎么办

1. 断点图标变灰时把鼠标放上去看原因。
2. 调试工具栏（或 `Run` 菜单）点「诊断断点」：列出游戏执行过的 chunk 名、每个断点的匹配结果；有建议的路径映射时可以一键应用。
3. 断点下发 5 秒后还没对上任何代码，控制台会出一条黄色提示，列出执行过的 chunk 名。**连这条都没有**，说明调试钩子没挂上：
   - Agent 面板里开着 UELink 的快照点或采样时，UELink 2.5.3 之前的版本会抢调试器的钩子。升级 UELink，或先撤掉快照点 / 停掉采样。
   - 控制台有「这个 Lua VM 和调试器的 Lua 接口不一致」：项目用的 Lua 被改过（UnLua 二次开发、改了 `LUA_IDSIZE` 或 `lua_Debug`），把这条信息和 Lua 版本发给我们。
4. 断点在只在某个时机执行的函数里（`Initialize` 在 Actor 构造时、`ReceiveBeginPlay` 在开始 PIE 时）：附加之后再触发那个时机。

## 性能

- 没有断点时游戏基本不受影响；断点在别的文件时，函数调用密集的代码会慢一些。
- **断点所在的函数会明显变慢**（每一行都要回调调试器，紧循环可能慢一个数量级）。调完记得删掉这类断点。

## 出问题时

- 调试器内部出错时只停掉那个 Lua VM 的调试，游戏继续运行，控制台有「调试器内部错误」。重新附加可以恢复；请把这条信息和 IDE 日志（帮助 → 显示日志）发给我们。
- 游戏崩溃：Release 页面有 `emmylua-windows-pdb-v<版本>.zip`，在 VS 里加载这些 PDB 能看到调试组件里的函数名和行号。
- 杀毒软件或防火墙拦截注入 / 本机端口时，把 IDE 插件目录下的 `emmy_tool.exe` 加入白名单。

完整的验收步骤见 [验收清单](../acceptance-checklist.md) 的 A、B 两节。
